# Instant, smooth Paris map load (vector map performance)

## Context

The raster→vector migration (PR #129) replaced Leaflet with MapLibre GL + CARTO Positron vector style in `app/components/ParisMap.js`. It looks great once loaded, but on phone/laptop the section shows a blank grey/white box for ~1s before the map pops in — everything (maplibre chunk, WebGL init, style.json, fonts, sprites, tiles, each on cold connections) is serialized behind a 400px-rootMargin IntersectionObserver, with no preconnect, no prefetch, and no graceful reveal. This ruins the luxury feel.

**Decision (user-approved, Option C):** do both — (A) make the real map genuinely faster, and (B) show a pre-rendered static snapshot of the exact map view instantly, with live HTML store dots on top, cross-fading to the interactive map when it's ready. Dots are NOT baked into the image (they'd go stale with the store list); the snapshot freezes only the basemap.

## Current-state facts (from exploration)

Center `[2.347, 48.857]`, zoom 12, container `height: 480px; background: #f4f4f5; isolation: isolate`. Markers/popups built synchronously after construction (~133–226). No `map.on("load")` handler, no fade-in.
- Usage: `app/page.js:3` static import; `AcrossParis` server component renders `<ParisMap stores={stores} />` inside `<Suspense fallback={<MapPlaceholder />}>` (placeholder covers only the streaming gap, not the MapLibre gap).
- `app/layout.js:58` preconnects only to `cdn.shopify.com`. No preconnect for `basemaps.cartocdn.com` / `tiles.basemaps.cartocdn.com` / `fonts.cartocdn.com`.
- `maplibre-gl@^5.9.0`, `next@16.2.0`, react 19.
- Font rule (CLAUDE.md): DOM injected outside React (popup card, zoom control) must reference the next/font CSS variable directly — the same applies to any new non-React DOM.

## Plan

### Part A — make the real map faster

1. **Preconnect to CARTO hosts** — in `app/page.js` (or the `AcrossParis` section) via `react-dom`'s `preconnect()`, matching the existing `cdn.shopify.com` pattern in `app/layout.js:58`: `https://basemaps.cartocdn.com`, `https://tiles.basemaps.cartocdn.com`, `https://fonts.cartocdn.com`. Verify the actual tile/glyph hosts by inspecting the live style.json's `sources`/`glyphs`/`sprite` URLs during implementation and preconnect to exactly those origins.
2. **Warm the maplibre chunk during idle time** — in ParisMap's mount effect, schedule `import("maplibre-gl")` (and the CSS import) via `requestIdleCallback` (with a `setTimeout(…, ~2500ms)` fallback for Safari), NOT synchronously on mount: an unconditional mount-time import competes with hero images and hydration on constrained phones — the very devices this change targets. The module registry caches the import; keep the IntersectionObserver solely to gate *map construction* (WebGL + tile fetches), and let an earlier intersection simply win the race with the idle warmup. The snapshot `<img>` must NOT be `priority`/preloaded — but it must not be `loading="lazy"` either: during the up-to-4s Suspense window ParisMap (and its observer) hasn't mounted, and lazy heuristics are non-deterministic, so a fast scroll could reach the section before the image — reintroducing the blank box. Use **`loading="eager"` + `fetchpriority="low"`**: the request starts deterministically with the document but yields bandwidth to hero/LCP resources.
3. **Await the CSS import** before `new maplibregl.Map()` — `await Promise.all([import("maplibre-gl"), import("maplibre-gl/dist/maplibre-gl.css")])` so the canvas never paints unstyled.
4. **Graceful reveal, with a failure path** — wrap the map div; start it at `opacity: 0` **and `pointer-events: none`**, transition to opacity 1 and re-enable pointer events on the map `"load"` event (fires when style + initial tiles are ready). This is the cross-fade over the snapshot.
   **Invariant: the transparent map layer must never sit interactive-but-dead over the snapshot.** If CARTO is blocked or partially unavailable, `"load"` may never fire; without the pointer-events gate the invisible canvas would swallow taps indefinitely. Add a bounded readiness fallback: on `map.on("error")` with a fatal style-load failure, or a ~12s timeout without `"load"`, call `map.remove()` and leave the snapshot showing (same graceful degradation as the existing no-WebGL catch at construction).

### Part B — static snapshot + live dots

5. **Snapshot generation script** — `scripts/generate-map-snapshot.mjs` (dev-only, run manually): uses Playwright headless (`npx playwright` — add as devDependency if not present; check first) to load a minimal local HTML page that constructs the same MapLibre map (same style URL, center `[2.347, 48.857]`, zoom 12, no markers/controls, `preserveDrawingBuffer: true`), waits for `map.on("idle")`, screenshots the canvas at **1600×480 @2x** (3200×960), and writes optimized WebP to `public/paris-map-snapshot.webp` (target ≲150KB; also a 1x fallback if size warrants).
   **License requirements for generation (CARTO Basemap Terms, verified):** (a) the script MUST send the CARTO key on every basemap request (same `transformRequest` `?key=` pattern as the live map) and **fail loudly if `NEXT_PUBLIC_CARTO_BASEMAPS_KEY` is unset** — CARTO may watermark tiles served to keyless requests, and a watermarked snapshot must never be checked in; (b) the script bakes a small legible "© CARTO © OpenStreetMap contributors" credit INTO the image, positioned inside the central ~350px horizontal safe zone at the bottom so no `object-fit: cover` crop at any viewport can remove it — the terms permit static images only when attribution is "legible in the image". The keyless-degradation contract for the LIVE map is unchanged (runtime keyless is permitted, merely watermarkable). Wide render + CSS centering means one asset serves all viewport widths. Document in the script header: re-run if the camera changes, if we change the style URL, **or if the cross-fade develops a visible jump** — CARTO can update the Positron style/tiles remotely without any code change here, so the checked-in snapshot can drift. Accepted risk, handled by manual regeneration; no automated drift detection (pinning/self-hosting the style or hash-checking tiles is overkill for a cosmetic, cross-fade-masked divergence).
6. **Snapshot layer in ParisMap AND in the Suspense fallback** — inside the existing 480px container, an absolutely-positioned `next/image` (or plain `<img>` with explicit dimensions, `priority`-loaded once near viewport) showing the snapshot: `position: absolute; inset: 0; object-fit: cover; object-position: center` — because the live map and the snapshot share the same center anchored at container center, cover-centering keeps them pixel-aligned at any width. The map canvas sits above it, fading in per step 4; after the fade completes, the img can be removed or left (it's occluded — leave it, simplest).
   **Invariant: the snapshot must NOT be gated behind the section's store fetch.** `AcrossParis` awaits `withTimeout(getActiveStores())` (`app/page.js`, `SECTION_TIMEOUT_MS = 4000`), so ParisMap streams in up to 4s late on a degraded store request — exactly the failure window the snapshot exists for. Extract the snapshot layer into a small shared presentational piece (e.g., `MapSnapshot`) rendered BOTH inside ParisMap and inside `MapPlaceholder` (the Suspense fallback in `app/page.js`), so the basemap image is visible from the document's first paint regardless of the section's store data. Dots and the live map still arrive with ParisMap. (Known residual, pre-existing and NOT fixed here: `app/layout.js:67-73` awaits `getActiveStores()` unbounded in the root layout — on a cold-cache instance with a *hanging* (not erroring) Supabase read, no HTML streams at all, fallback included. That gap predates this plan and is sitewide, not map-specific.)
   **Attribution invariant (license requirement):** the snapshot is a CARTO/OSM basemap render, and on the failure path it can remain the *final* experience — an unattributed basemap would violate the CARTO license the current code explicitly honors in production. Primary compliance is the credit **baked into the image** (step 5) — required by CARTO's static-image clause regardless of surrounding DOM. Additionally, `MapSnapshot` renders the same whisper-styled *linked* CARTO + OSM attribution overlay as the live map (reuse the `div.maplibregl-map` attribution styling conventions from `app/globals.css`) so the credit is clickable and matches the live map's placement; it sits inside the snapshot layer, so the live map — which brings its own AttributionControl — naturally occludes it on reveal: no duplication, no omission. Compliance basis note: CARTO's terms permit "screenshots or other static images … for illustrative, editorial or documentary purposes" with in-image attribution; this loading stand-in relies on that clause, generated with a valid key.
7. **Live static dots** — a small pure function `lngLatToCenterOffsetPx(lng, lat, center, zoom)` implementing Web Mercator: pixel offset from container center = `(mercX(lng) − mercX(centerLng)) · 512 · 2^zoom` (and same for y with the latitude mercator). Render one absolutely-positioned 12px dot per store (same styling as the live markers, built in React this time) over the snapshot, positioned with **CSS `left: calc(50% + <dx>px); top: calc(50% + <dy>px); transform: translate(-50%, -50%)`** — no container measurement at all. Because the offsets are center-relative constants, CSS keeps dots aligned through any resize/orientation change with zero JS (no layout effect, no ResizeObserver), matching the live map's own recentering behavior. They are **visual only** (no popups) and fade out as the live map fades in, replaced by the real MapLibre markers.
8. **Zoom constant shared** — extract center/zoom into module-level constants used by both the live map and the projection math so they can't drift.
