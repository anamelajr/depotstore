# Formatting-audit issue #114 — triage, root causes, and fix plan

## Context

The daily formatting audit (PR #113) filed 124 violations + 109 review-tier items
into issue #114. Task: assess validity, explain why each class exists, and fix.
User decisions (2026-08-17):

- **Add a Swimwear category** to the taxonomy (largest chunk of NULL-category rows).
- **Collab/sub-line titles**: keep the sub-line identity, strip redundant parent-brand words.
- **Scope**: code + config fixes in a PR; data backfills documented as follow-up
  SQL / script runs (Supabase SQL Editor + sanctioned dry-run scripts), not in the PR.

## Assessment — the findings are valid; three buckets

**1. Legacy data locked by write-once (~110 of 124).** `enrich_product` is
COALESCE write-once, so any row enriched before a rule/alias existed can never
be repaired by the pipeline — only by sanctioned backfills.

- `non_canonical_brand` (29: 28× BIKKEMBERGS, 1× A.P.C): aliases already exist
  in `BRAND_ALIASES` (`app/lib/brand.js:13,30`); rows predate them. Pure data fix.
- `enrichment_failed` (76, all `NULL: category`): brand/title written fine;
  `assignCategory` structurally returned null (see bucket 2) and the row burned
  its 3 attempts (`MAX_ENRICH_ATTEMPTS = 3`, `app/lib/enrichLimits.js:6`).

**2. Config/taxonomy gaps (the systemic causes).**

- **Swimwear is explicitly null-guarded**: `SWIMWEAR_RX`
  (`app/lib/category-classifier.js:159`, short-circuits at `:267-269`, `:293-295`)
  matches swimsuit/bikini/trikini/swimwear/bathrobe → `{category: null}` until a
  taxonomy slot exists. Dominates the 76 failures.
- **Classifier vocabulary gaps**: "Bayonetta" (chezsnowbunny slang for narrow
  sunglasses — confirmed by user), "harness", "kilt", "pillow", and French nouns
  ("Vestes", "Debardeur", "Foulard", "Cabas", "Pareo") match no regex.
- **Missing brand aliases** (3 families, no `BRAND_ALIASES` entry, so stored
  labels drift): A.F VANDEVORST / A.F. VANDEVORST, JW ANDERSON / J.W. ANDERSON,
  Y-PROJECT / Y/PROJECT. All are allowlist-equivalent via normalize/compact fold,
  which is why they were accepted with divergent spellings.
- **Missing `SUB_LINE_PREFIXES` entries**: the 3 `season_not_first` hits are
  really sub-line leaks — `Y's` (Yohji Yamamoto), `London` (John Galliano),
  `Boutique` (Valentino). Map lives at `app/lib/handleFallback.js:109-114`.

**3. Deliberately manual (~7 rows).** The season normalizer refuses to guess:
`A2013` (bare_letter_year), `FW90s` (decade_with_season_prefix), `SS19999`
(overlong_year) are flagged-not-fixed by design (`app/lib/seasonCodes.js:99-107` —
auto-fixing would invent a season). Plus trailing-"By" id 14953917 and the 6
`brand_in_title` collab rows. Hand-edited SQL only.

### The Saddle-bag / Bayonetta mystery (user questions, answered from live rows)

Row 14942240 "Saddle Olive-brown Crocodile Embossed":
- Vendor `name` = "Dior Saddle Olive-Brown Crocodile Embossed"; Shopify
  `description` (body_html) is **empty**. `cleanTitle` may only use details
  present in the source name/description (`cleanTitle.js:139`), so it correctly
  did not invent "Bag". The retailer never says "bag" anywhere.
- The description on the site that *does* say "bag" is **not the retailer's** —
  it's `editorial_description`, generated by our own `generateDescription`
  OpenAI call on first PDP visit (`app/lib/resolveProductDetail.js:192-204`).
  The model knows from world knowledge that a Dior Saddle is a bag.
- The classifier's pass 4 *does* read `editorial_description`
  (`category-classifier.js:305-311`) — but enrichment exhausted its 3 attempts
  **before** anyone visited the PDP, so the editorial description didn't exist
  yet. Chicken-and-egg. Re-running `scripts/backfillCategories.mjs` today
  classifies this row correctly (pass 4 sees "Saddle bag …").
- The 6 "Bayonetta" rows (14942076/78/83/86/87/91) are sunglasses with empty
  descriptions and no eyewear word in the title → vocabulary fix below. Their
  titles are acceptable as-is; category comes from the new classifier term.


Note: majority of stored rows use `J.W. ANDERSON` (2 vs 1) but the allowlist

of truth. These entries also make the audit's `non_canonical_brand` rule start
flagging the drifted rows until the backfill runs — expected and correct.

### B. Sub-line prefixes — `app/lib/handleFallback.js` (`SUB_LINE_PREFIXES`)

```js
"yohji yamamoto": ["Y'S", "POUR HOMME"],
"john galliano":  ["LONDON"],
"valentino":      ["BOUTIQUE"],
```

Mind the apostrophe: `leadingSubLinePrefix` (`app/lib/formattingHealth.js:101-110`)
builds a regex from the prefix — `Y'S` must match both `'` and `’` in titles
(row 15239796 uses `’`). Escape/normalize accordingly (small tweak to the regex
build or store the prefix as a pattern-safe form). Effect: the 3
`season_not_first` items reclassify to `sub_line_prefix` (correct key; the fix
for the titles themselves is a strip, done in the follow-up SQL).

### C. Swimwear category — taxonomy + classifier

- `app/lib/category-classifier.js`: convert the `SWIMWEAR_RX` null-guard

- Per CLAUDE.md, do the parallel pass: confirm `resolveCategoryFilter` and the
  interleaved RPCs need no SQL change (they compare against passed category
  strings, no enumeration — verify, don't assume). No DB DDL expected; the
  `products_subcategory_matches_category` CHECK is untouched (no subcategory).

### D. Classifier vocabulary — `app/lib/category-classifier.js`

Add high-confidence terms observed in the failing 76 (word-boundary, in both
the parent regex and the matching leaf regex where applicable):

- `bayonetta(s)?` → Bags & Accessories / accessories (sunglasses slang).
- `harness` → Bags & Accessories / accessories.
- `kilt` → Dresses & Skirts.
- `pareo|sarong` → Swimwear (beach cover-ups).
- French garment nouns (chezsnowbunny rows): `veste(s)` → Jackets & Coats,
  `débardeur/debardeur` → Tops, `foulard` → Bags & Accessories/accessories,
  `cabas` → Bags & Accessories/bags.

Do NOT add speculative terms (e.g. "pillow"/homeware — out of taxonomy; those
rows legitimately stay null).

### E. Harden `scripts/backfillCategories.mjs` for scoped repair

As written the script is a full-table rewrite: it scans every row, omits
`productType` (which the cron HAD at sync time), and overwrites any
disagreement — so a `--write` run today could flip currently-valid categories
to different values or NULL, with no compare-and-set, no transaction, and no
abort on batch failure. For this repair add:

- `--only-null` flag: scan filter `.is("category", null)` (the actual repair
  target), and a matching CAS predicate on the write —
  `.update({ category }).in("id", slice).is("category", null)` — so a
  concurrently-changed row is never clobbered. Rollback is then trivial
  (prior value was NULL; snapshot the id list before writing).
- Abort nonzero on the first failed batch instead of continuing.
- Print the exact id list written (rollback input).

The legacy full-table mode stays available but is NOT part of this repair.

## Follow-up data repairs (documented, run manually — NOT in the PR)

Order matters: merge + deploy the PR first, then:

1. **Brand normalization SQL** (Supabase SQL Editor, snapshot first):
   `UPDATE products SET brand='DIRK BIKKEMBERGS' WHERE brand='BIKKEMBERGS';`
   and same for `A.P.C`→`A.P.C.`, `A.F VANDEVORST`→`A.F. VANDEVORST`,
   `J.W. ANDERSON`→`JW ANDERSON`, `Y-PROJECT`→`Y/PROJECT`.
   Fixes all 29 `non_canonical_brand` + all 5 `split_brand_family`.
2. **Category backfill — scoped, never full-table**:
   `node scripts/backfillCategories.mjs --only-null` (dry-run, review every
   transition) then `--only-null --write`. With C+D+E deployed this rescues
   swimwear, bayonetta, harness, kilt, French-noun rows, and the Saddle bag
   (via its now-present editorial_description) while touching ONLY rows whose
   category is NULL — currently-valid categories cannot be rewritten. Expect a
   small residue of truly unclassifiable rows — they stay NULL and reported;
   triage those by hand afterwards.
   **Do not run without `--only-null`**: the full-table mode re-classifies
   without `productType` (which the cron had at sync time) and can flip valid
   categories to different values or NULL.
3. **Subcategory backfill** (fills the leaf the step above cannot):

   emitted SQL is parent-gated (skips cross-category disagreements, honouring
   `products_subcategory_matches_category`) and snapshots prior values into
   `products_subcategory_backfill_snapshot` first. Swimwear has no leaves —
   unaffected.
