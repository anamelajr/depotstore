# Mobile Product Page Redesign + Global Footer — Design Doc

**Date:** 2026-05-02
**Author:** Brainstorming session
**Status:** Draft for review

## Goals

Redesign the mobile product page (`app/product/[handle]/page.js`) so that it reads as an editorial moment rather than a utilitarian product readout. Inspired by the Rick Owens product page reference shared during brainstorming: brand label as the dominant typographic anchor, generous whitespace, calm rhythm, primary action prominent.

At the same time, introduce a single global `Footer` component used on every page of the site, replacing the homepage's inline footer and adding a footer to pages that don't currently have one.

## Out of scope

- **Desktop PDP** — the existing desktop layout (sticky thumbnail column, hero image, sticky info pane) is not being changed in this design. Tailwind responsive breakpoints separate the two.
- **Shipping & Returns accordion** — explicitly skipped. No new data, no schema change, no accordion. May be revisited later.
- **Schema changes** — no new columns on `products` or `stores`. No new RPCs. No data migrations.
- **Save backend rework** — Save reuses the existing `/saved` flow as-is. The PDP only adds the entry point.
- **Editorial description regeneration** — the existing `generateDescription.js` flow is preserved unchanged. We only move where the description is rendered.
- **Title typography on browsing/feed pages** — those keep their current ProductCard treatment. The new mono brand label is scoped to the PDP.

## Architecture overview

The redesign is purely presentational and structural:

- The PDP's mobile branch (`lg:hidden` portion of the layout) is rebuilt around a new visual rhythm. The desktop branch (`hidden lg:flex`) is preserved.
- A new `Footer` component is created and added to the root layout so it appears site-wide.
- Two new components are introduced: an `Accordion` primitive (used twice — Description and Store Profile) and a `MoreFromStore` row (4-product grid). Both are PDP-scoped.
- Save and Share are added as small client components on the PDP. Save delegates to the existing `/saved` mechanism. Share uses the browser's native Web Share API with a fallback to copying the product URL to the clipboard.

No backend changes. No new database columns. No new API routes.

## PDP layout — top to bottom (mobile)

The mobile flow, as scrollable sections:

### 1. Image carousel
- Existing `ProductGallery` swipe carousel kept, including the side arrows and dot indicators that ship today.
- Image stays in a contained card (padding around the image edges).
- No data changes — uses the same `images` array from Shopify's `/products/{handle}.json`.

### 2. Brand + title block
- **Brand label** — mono uppercase, 22px, font-semibold, letter-spacing ≈ 0.06em. The dominant typographic element.
- **Product title** — Inter sans, 14px, regular weight, mixed case, muted color (`text-zinc-600`).
- Tight vertical rhythm between them (~10px). The block sits roughly 24px below the carousel's dot indicators.

### 3. Price + meta block
- 32px gap above. Mono captions, line-height generous.
- Price (existing logic).
- Store name (clickable, links to that store's page).
- Size (derived from Shopify variants; if a single "One Size" variant, render that; otherwise list comma-separated).

### 4. Primary CTA
- 36px gap above.
- Full-width black button, padding ~18px, mono caption: "View at retailer ↗".
- Existing `productUrl` with `?utm_source=depot`.

### 5. Save / Share row
- 20px gap above. Two flex-1 cells, no borders, no vertical divider.
- Each cell renders an icon + label, centered, mono.
- Save: bookmark icon, label "Save". Reuses existing `/saved` mechanism.
- Share: upload arrow icon, label "Share". Calls `navigator.share` with `{ title, url }` if available; falls back to `navigator.clipboard.writeText(productUrl)` plus a transient "Copied" state.

### 6. Accordions
- 40px gap above. Two accordions stacked.
- **Description** — body is the existing `editorial_description` value (lazy-generated by `generateDescription.js` on first PDP view, persisted to `products.editorial_description`).
- **Store Profile** — body pulls from existing `stores` table fields available today (e.g. `name`, `domain`, address-style metadata if present). If only `name` and `domain` are available, the body is a brief note + a link to that store's `/stores/[domain]` page.
- Each row: header with label + collapsible chevron `+` / `−`, hairline divider in `#f4f4f5`, expanded body in Inter sans 13px.
- Both default closed.

### 7. More from this store
- 64px gap above.
- Section label in mono uppercase ("More from {Store Name}").
- 2×2 grid of 4 cards. Each card: image (3:4), brand (mono caption), title (Inter sans), price (mono).
- Sourced from the existing `/api/products` route, filtered by `store={current_store_domain}`, sorted `newest`, `limit=5`, with the current product filtered out client-side. We over-fetch by one to handle the case where the current product is in the result set.
- Cards link to the same product page route.

### 8. Global footer
- See the Global Footer section below. Same component as every other page on the site.

## Typography decisions

| Element | Treatment | Rationale |
|---|---|---|
| Brand label | Mono uppercase, 22px, semibold, tracking 0.06em | Same font family as the existing ProductCard brand label, scaled up. Becomes the visual anchor of the PDP. |
| Product title | Inter sans, 14px, regular, mixed case, muted color | Secondary to the brand. Matches the existing site convention of Inter sans for product names. |
| Price | Mono, 13px, dark zinc | Existing convention preserved. |
| Store row | Mono, 11px, mid zinc, with `›` chevron | Visually grouped with size. |
| Size row | Mono, 11px, mid zinc | New row — derived from Shopify variants. |
| CTA | Mono, 12px, light tracking, white on black | Existing CTA convention preserved, restyled to a full-width button. |
| Accordion headers | Mono, 11px, dark zinc | Caption-like, matches site rhythm. |
| Accordion bodies | Inter sans, 13px, mid zinc, line-height 1.7 | Existing description copy treatment preserved. |
| Section labels | Mono uppercase, 11px, tracking 0.18em | Existing convention from "Today's Edit" / "Across Paris". |

No new fonts are introduced. The site's existing Inter sans + system mono pairing is preserved everywhere.

## Components

### `app/product/[handle]/page.js`
- Server component, mostly preserved.
- Mobile section is rebuilt around the new layout.
- Variants are mapped to a size string for the size row.
- Currently fetches one extra "more from" product set so the same-product can be filtered.

### `app/components/ProductGallery.js`
- Unchanged. Existing swipe + arrows + dots behavior is kept.

### `app/components/Accordion.js` (new)
- Client component. Props: `label`, `children`, `defaultOpen` (default false).
- Renders header row with `+` / `−` icon, body collapses with `display:none` on closed (no animation in v1, can be added later).
- Used twice on the PDP.

### `app/components/SaveShareRow.js` (new)
- Client component. Props: `productUrl`, `productHandle`, `storeDomain`, `title`.
- Two flex-1 buttons.
- Save: hands off to the existing saved-page wiring (the `/saved` page already exists per recent commits — we'll bind to whatever store/handle key it uses).
- Share: tries `navigator.share({ title, url: productUrl })`; if unavailable or rejected, copies `productUrl` to clipboard and toggles a brief "Copied" label for 2s.

### `app/components/MoreFromStore.js` (new)
- Async server component that fetches via `/api/products?store={domain}&sort=newest&limit=5`.
- Filters out the current product by `handle`, slices to 4.
- Renders 2×2 grid using the existing `ProductCard` component (or a stripped variant) — TBD in implementation plan based on what fits cleanly.
- If fewer than 4 products are available, renders whatever is available (no padding).

### `app/components/Footer.js` (new)
- Server component. Renders the dark-mode footer (see Global Footer section).
- Used in `app/layout.js` so it appears site-wide.

## Data flow

| Element | Data source | Change vs. today |
|---|---|---|
| Product image | Shopify `/products/{handle}.json` | None |
| Brand | `products.brand` (Supabase) → fallback `product.vendor` (Shopify) | None — existing logic preserved |
| Title | `products.title` (Supabase) → fallback `product.title` (Shopify) | None |
| Price | Shopify variants, min price | None |
| Store row | Shopify `storeDomain` searchParam → look up store name from `stores` table | New: render the store name + link |
| Size row | Shopify variants array | New: render `One Size` if single variant, else comma-joined |
| Description body | `products.editorial_description` (Supabase), lazy-generated | None — same source, just rendered inside accordion now |
| Store Profile body | `stores` row | New rendering of existing data |
| More from this store | `/api/products?store={domain}&sort=newest&limit=5` | New consumer of an existing endpoint |

## Global footer

A single `Footer` component used on every page on the site. Replaces the homepage's existing inline footer.

**Visual structure:**
- Black background (`#0a0a0a`), white-on-dark text
- Generous vertical padding (~64px)
- DÉPÔT logotype (Inter bold 32px, uppercase, tight tracking)
- Tagline: "Paris. Archive. One feed."
- Newsletter signup using the existing `NewsletterForm` component
- Two columns:
  - **Explore** — Feed (`/feed`), Stores (`/stores`), Saved (`/saved`)
  - **Connect** — Contact (`mailto:hello@depot.paris`, the existing nav drawer link), Instagram (URL TBD by user)
- Bottom row: copyright (`© 2026 Dépôt`) and "Paris" caption

**Where it appears:**
- `app/layout.js` — the root layout. The footer is rendered after `{children}` so it sits below every page's content.
- `app/page.js` — the existing inline footer block is removed; the global footer takes its place. The `NewsletterForm` mount in the homepage's existing footer moves with it.

## Save behavior

- v1 scope: visual-only toggle. The PDP Save button toggles a local React state inside `SaveShareRow` — clicking fills the bookmark icon, clicking again unfills it. State does not persist across page navigation or browser sessions.
- This was an explicit scope decision: `/saved` is currently a "Coming soon" stub (`app/saved/page.js`). Building a real persistence layer (localStorage, DB, or auth-based) is out of scope here and will get its own spec.
- The button is wired so that when a future Save mechanism lands, only `SaveShareRow.js` needs to change; no other PDP code touches save state.

## Share behavior

- `navigator.share({ title, url: productUrl })` if available (most modern mobile browsers). The OS native sheet handles the rest.
- Fallback for unsupported environments: copy `productUrl` to clipboard via `navigator.clipboard.writeText`, then briefly swap the label to "Copied" for 2 seconds.
- No analytics integration in v1.

## Spacing system

Vertical spacing between blocks (mobile):

- Image card to brand block: 24px
- Brand to title (within block): 10px
- Title block to price/meta block: 32px
- Within price/meta block: 14px between rows
- Meta block to CTA: 36px
- CTA to Save/Share row: 20px
- Save/Share row to accordion stack: 40px
- Accordion stack to "More from this store": 64px
- "More from this store" to footer: 56px (ends section)

Horizontal padding for content blocks: 24px.

Dividers use `#f4f4f5` (almost invisible) so visual separation is driven by whitespace, not lines.

## Risks / open items

- **Save persistence is deliberately deferred.** v1 uses an ephemeral toggle inside `SaveShareRow`. A future spec covers real persistence + an updated `/saved` page that lists items.
- **Store Profile body content** — depending on what columns exist on `stores`, this accordion body may be very thin. If it ends up just being store name + a link, the implementation may collapse it to a simpler footer row instead. Decide during implementation by looking at `stores` row shape.
- **Web Share API fallback** — clipboard write requires HTTPS; on localhost over HTTP it may fail silently. CLAUDE.md already says verify on Vercel, so this is not blocking.
- **Image gallery touch behavior** — the existing `ProductGallery` is preserved. If the new visual rhythm exposes an existing bug (e.g. wheel-to-navigate on desktop, scroll restoration), that bug is out of scope here.

## Verification

Per CLAUDE.md, behavioral verification happens on Vercel preview, not localhost. Each major change should be verified in the Vercel preview before merge:

- Mobile PDP renders the new layout end-to-end with real Shopify data
- Brand falls back from `products.brand` → `product.vendor` correctly when the editorial brand is null
- Description accordion shows existing `editorial_description` content; lazy-generation still triggers on first view
- Save persists across page refreshes via the existing `/saved` mechanism
- Share opens the native sheet on mobile Safari/Chrome; falls back to clipboard on desktop
- "More from this store" shows 4 distinct products from the same store, never including the current product
- Global footer appears on homepage, feed, stores, saved, product, and any other route
- Newsletter signup in the new footer still posts to `/api/subscribe` (Beehiiv) successfully
- Desktop PDP layout is unchanged

## Decisions log

For posterity, the choices made during brainstorming and the reasoning:

1. **White background, not cream** — kept consistent with the rest of the site. The cream from the original reference would have been a separate brand-level shift.
2. **Side arrows kept on the image carousel** — user preference; the Rick Owens style of dots-only was considered but rejected.
3. **Mono brand label, not serif** — earlier iterations explored Cormorant Garamond serif. User explicitly preferred the existing site fonts. Mono caps anchor + Inter sans title is the final hierarchy.
4. **Brand bigger than title (inverted hierarchy)** — Rick Owens reference made this choice. Brand becomes the visual anchor; title sits underneath as supporting copy.
5. **Skip Shipping & Returns** — the editorial summary path was sketched but ultimately dropped to keep scope focused. The "View at retailer" CTA already directs users to the retailer's own policies.
6. **More from this store, not Curated Pairings** — keeps the design honest to what we can implement well today (same-store query) instead of inventing a similarity model.
7. **Global footer, not PDP-only** — site-wide consistency wins. The existing homepage footer is replaced rather than left as a one-off.
8. **No Save / Share borders** — earlier iterations had borders around the row. Reference image shows borderless — adopted.
